INVENTORY SYSTEM - MISSING COLUMNS FIX
================================================================================

PROBLEM:
--------
The order_items table was missing critical columns (product_id, size, color, sku, 
variant_details, variant_id) that are needed to properly connect orders with the 
product_variants table for inventory tracking.

This caused the inventory reduction triggers to fail because they couldn't match 
order items to product variants, resulting in stock quantities not being reduced 
when orders were completed.


SOLUTION IMPLEMENTED:
--------------------

1. DATABASE SCHEMA CHANGES
   ✅ Added 6 new columns to order_items table:
      - product_id (TEXT) - Product identifier
      - size (TEXT) - Variant size  
      - color (TEXT) - Variant color
      - sku (TEXT) - Product SKU
      - variant_details (JSONB) - Full variant information
      - variant_id (UUID) - Foreign key to product_variants

   ✅ Created 5 new indexes for fast lookups:
      - idx_order_items_product_id
      - idx_order_items_size
      - idx_order_items_color
      - idx_order_items_sku
      - idx_order_items_variant_id

2. TRIGGER FUNCTIONS UPDATED
   ✅ reduce_inventory_on_public_order() - For Stripe orders
   ✅ reduce_inventory_on_order() - For analytics orders
   
   Both now use 4-strategy matching system:
   1. Direct variant_id reference (most reliable)
   2. SKU match
   3. product_id + size + color match (most accurate)
   4. Variant name parsing (fallback)

3. CODE UPDATES
   ✅ src/services/supabaseIntegration.ts
      - Parses size/color from variant strings
      - Maps product names to product_ids
      - Populates all new columns when creating order_items
   
   ✅ analytics-backend/supabase/functions/stripe-webhook/index.ts
      - Extracts variant details from Stripe line items
      - Populates all new columns
   
   ✅ netlify/functions/stripe-webhook.js
      - Extracts variant details from Stripe line items
      - Adds variant information to cart items
